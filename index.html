03 — Work

The site I built and run

A site I built from scratch and use as a live SEO testing ground — applying on-page and technical fixes, tracking them in Search Console, and learning from what actually moves.

StackSignal

Live

What it is: A tech & AI blog I built from scratch as a working SEO test rig — a dependency-free static site generator in Node that turns one content file into HTML pages, a search index, sitemap, RSS and schema markup.

I built it SEO-complete from day one rather than bolting optimisation on later: unique title, meta description and canonical on every page; Open Graph and Twitter cards; and structured data covering BlogPosting, BreadcrumbList, FAQPage, Organization and WebSite with SearchAction. Semantic HTML throughout — one H1 per page, logical H2→H3, descriptive anchors and no orphan pages.

Performance and accessibility are treated as ranking co-factors: static HTML, a single CSS file, ~8KB of deferred JS, font preloading, long-lived asset caching, plus a skip link, focus-visible rings, an ARIA combobox search and reduced-motion support.

Content is deliberately clustered rather than scattered — 7 published posts across two topic clusters (Core Web Vitals / performance, and AI / LLM workflows), interlinked so each cluster can build topical authority instead of competing with itself.

A real bug I diagnosed and fixed: Search Console reported the sitemap as “couldn’t fetch.” Auditing the live site against the source, I found the homepage was declaring its canonical URL as /index.html while readers and crawlers actually arrive at the bare root — the same page claiming two addresses, with the non-standard one marked as official.

I consolidated the homepage canonical, the sitemap entry and the breadcrumb structured data onto a single root URL so all three agree, verified the rebuilt sitemap served correctly, then cleared the cached error in Search Console and requested indexing on the priority pages. Along the way I also traced the deployment itself — the site builds and ships through a GitHub Actions pipeline, and an earlier stale build was masking what was actually live.

Currently: growing each cluster with supporting posts, and tracking impressions, average position and CTR per cluster in Search Console.
